# Q-Manipulation Reward Transfer Experiments

This repository curates the code used for the TMLR paper *Provably Efficient Reward Transfer in Reinforcement Learning with Discrete Markov Decision Processes*. The paper studies reward adaptation in discrete MDPs and evaluates Q-Manipulation (Q-M) and Monotonic Q-Manipulation (M-Q-M) against Q-learning and SFQL across fixed gridworlds, autogenerated MDPs, and noisy reward mappings.

The original project folder already contains the paper-era experiment scripts and local result artifacts, but the workflow was fragmented: each domain had its own handwritten script order, manual averaging step, and plotting entrypoint. This repository layer fixes that by adding:

- a single top-level runner for collect / aggregate / plot stages
- a paper-aligned experiment registry with stable names
- generic CSV aggregation so averaging is no longer duplicated by hand
- Git metadata and ignore rules so generated artifacts do not overwhelm the repository

## Quick Start

Install the package in editable mode:

```bash
python -m pip install -e .
```

List the curated experiment workflows:

```bash
python run_experiments.py list
```

Show the exact scripts and outputs for one experiment:

```bash
python run_experiments.py show dollar-euro
```

Run a full paper workflow for one domain:

```bash
python run_experiments.py run dollar-euro --stage all --start 0 --end 30
```

You can also run only the aggregation or plotting stage after raw seed runs already exist:

```bash
python run_experiments.py run racetrack --stage aggregate
python run_experiments.py run racetrack --stage plot
```

The curated runner intentionally wraps the legacy scripts instead of rewriting the algorithm implementations in-place. That keeps the paper code intact while making the user-facing workflow predictable.

## How The New Workflow Works

Each curated experiment is defined as:

1. a `collect` stage that runs the relevant legacy scripts in the right order
2. an `aggregate` stage that concatenates per-seed CSV outputs into the final experiment-level CSVs
3. a `plot` stage that reuses the original plotting script for that domain

The runner supports:

- `--stage collect` to generate or refresh raw per-seed results
- `--stage aggregate` to build final CSVs used in the paper figures
- `--stage plot` to render the final figure from those aggregated CSVs
- `--stage all` to run the full workflow end to end

Use `--dry-run` if you want to inspect the exact command sequence before executing anything.

The canonical legacy collect scripts were also cleaned up to accept `--start` and `--end` directly, so they no longer require interactive prompts when used in automation.

## Generated Artifacts And Git Hygiene

The folder already contains many generated artifacts: seed folders, CSV outputs, NumPy arrays, pickles, and rendered figures. These are treated as generated artifacts and are excluded from Git through `.gitignore`. The intent is:

- source scripts stay visible and reviewable
- large local outputs stay on disk but do not clutter commits
- duplicate and supplemental folders such as `rebuttal/`, `heatmaps/`, and `Exp 1 Fixed MDP FIxed R - Copy/` stay available locally but outside the curated repository view

## Notes On Legacy Coverage

This curation layer focuses on the paper’s main experiment paths from Sections 4.3 through 4.5. Legacy exploratory scripts, rebuttal-era analyses, and duplicate copies were left in place locally instead of being deleted. That is deliberate: the repository now has a clean default interface without discarding potentially useful historical material.

If you want to extend the curated runner to more domains or rebuttal experiments, add a new entry in `src/qmanip/experiments.py` and point it at the relevant legacy script sequence.
